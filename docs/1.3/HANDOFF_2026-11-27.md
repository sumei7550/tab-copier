- 插件移除误导性的公开 `Check purchase`，改为同一个「恢复购买」入口：本地已付订单、现有授权、已确认恢复申请均可处理；确需人工时准备恢复申请并打开客服引导。Pro 激活后隐藏恢复入口。
- 恢复邮件模板含参考编号、购买联系邮箱、可选 PayPal 付款邮箱/交易号。参考编号绑定当前安装，不能当作购买证明。普通反馈不自动建立恢复申请。
- 管理员签发备注显示至少 8 字符和字数。原先仅填“数据库”导致按钮置灰的问题已说明并补提示。

## 明天换电脑

新电脑安装 Git 与 Node.js 24。拉取 `main` 后，在仓库根目录构建扩展：

```powershell
git clone https://github.com/sumei7550/tab-copier.git
cd tab-copier
node scripts/build-extension.mjs --api-base https://tab-copier-sandbox.vercel.app --public-key extension/sandbox-public-key.pem
```

Chrome 开启开发者模式，加载**生成的 `build/extension-sandbox`**。不要直接加载仓库根目录：根目录默认配置是 localhost 且无付款公钥。

`extension/sandbox-public-key.pem` 是当前沙盒验签公钥，可安全随仓库保存；它不是私钥，也不能签发授权。`website/.env.local`、服务端密钥、依赖和构建输出不进 Git。新电脑直接构建沙盒扩展不需要 PayPal/Supabase 密钥。

需要本地运行网站测试时：

```powershell
cd website
npm ci
npm test
npm run build
node --experimental-strip-types scripts/test-admin-http.mjs
```

本地纯测试不需要真实支付配置。实际管理恢复直接登录 Vercel 管理页；如需本地接真实沙盒，由管理员从既有安全配置来源单独配置，不把密钥贴进聊天或提交仓库。**不要运行 create-sandbox-keys 来“解决”换电脑配置问题。**

新电脑会有新的随机安装标识，插件本地授权和恢复请求不会自动从旧电脑搬过去。需在新安装发起恢复申请并用新参考编号处理；发给旧安装的链接不能用来授权新安装。
