# 1.3 UI 设计说明

管理员恢复页面与付款联系邮箱补充：见 `ADMIN_RECOVERY.md`。管理界面沿用现有 Next.js、原生表单、主色和面板风格，按登录 → 核查订单 → 确认归属 → 回复邮件组织；不重构插件。订单核查不直接签发，成功页保留链接和复制失败时的手动复制方式；窄屏表单与订单详情改为单列。管理入口不放在购买主流程中。购买联系邮箱在套餐按钮前填写，并有数据使用说明，历史订单可缺省。

状态：2026-11-27 评审稿，自动激活版本。依据 docs/RELEASE_1.3_PLAN.md；原型为本地模拟，不处理真实支付。以 DEVELOPMENT_DESIGN.md 自动激活规则为准。

## 项目认知与设计门槛

- 阶段：现有扩展迭代，新增购买/授权流程。
- 用户：把浏览器标签链接粘贴到笔记、文档和聊天的人。
- 对象：复制范围、标签选择、输出格式、套餐、订单、授权。
- 入口/主任务：点击工具栏 → 选择范围和格式 → 预览 → 复制；需要 Pro 时进入套餐页 → PayPal → 核款 → 插件自动激活。
- 首个决策：要复制哪些标签。信息顺序为范围、格式、选择、输出和操作；额度不抢占主任务。
- 成功：复制内容与预览一致；购买后插件能自动取得并使用授权。
- 恢复：配额耗尽可升级；支付待确认可重查；激活失败保留购买会话并可重试；不因网络错误直接降为免费。
- 移动端：购买/确认页可单列使用；扩展弹窗保持桌面紧凑布局。
- 气质：简单、明确、克制。基础为原生 HTML 表单和现有 CSS，不引入整套组件库；参考现有 Tab Copier 与 Chrome 原生控件。
- 不在主界面出现：数据库、Webhook、支付密钥、HTTP 状态堆栈。
- 风险：收费入口抢占复制按钮、长标题溢出、弹窗超高、到期后预览与输出不同。
- 验证：检查 380px 弹窗、窄屏购买页、键盘操作、空/错误/等待/成功状态；此稿不等同于实机扩展验证。

## 布局与组件

弹窗宽 380px，内边距 16px，控件至少 32px，复制按钮至少 38px；总高度控制在 600px 内，标签列表与预览内部滚动。字体 system-ui 13px，正文 #202124，辅助文字 #60646c，主色 #4f5de4，边框 #dfe3eb，焦点使用清晰外圈。锁定项必须包含 Pro 文字，不能仅靠颜色表达。

页头保留名称、全选和选择数量；下一行显示剩余次数/Pro 状态和升级/管理入口。范围与格式各有明确标签；Markdown 样式独立一行。去重选项显示 Pro 标记。付费控件可触达并解释权益，不用完全禁用导致无说明。未分组范围禁用并给出原因。

原型提供免费、额度耗尽、已购买、已过期、未分组、空结果和授权服务异常场景。测试场景控制器仅存在于演示外壳，不能进入产品。

## 页面与文案

1. 弹窗：复制选中项是唯一主操作。普通 Markdown 免费；付费列表样式点击后展示升级页，取消后保留原选项。
2. 套餐页：三个套餐同权益，明确 USD、使用时长、非续费和体验限购；不默认勾选协议、不伪造折扣。付款前展示本次选择。
3. 支付确认页：区分付款待确认、已付款待激活、自动激活成功和服务异常；不展示任何激活码，提示返回插件或重新检查。返回页面不等于付款已确认。
4. 恢复购买：先检查本设备凭证；凭证仍在可自动刷新，凭证丢失则展示 sumei7550@outlook.com、复制邮箱、复制邮件模板和打开邮件应用。可生成恢复请求编号供人工绑定目标插件；不展示在线邮箱恢复表单，不自动发邮件。
5. 恢复链接页：确认恢复到本次申请的插件，显示“确认恢复”；仅查看页面不消费链接。无效/过期/已用明确提示重新联系支持，不暴露订单或授权秘密。成功后回插件复查。
6. 设置页沿用现有布局，显示套餐/到期时间、重新检查授权、恢复购买；与 popup 共享去重和权益判断。

用户无需保存或输入激活码。内部令牌不出现在 UI。Buy me a coffee 保留为次要入口。套餐页明确 USD、非自动续费、首次自动激活起算；体验限购能力以可信付款标识为限，不宣称跨账户严格防绕过。

## 评审与边界

本次交付以中文说明交互，正式版本覆盖现有 13 个 locale。老用户权益、设备数量、续购合并、离线宽限时长与恢复服务时限仍待确定；原型不替这些问题作最终决定。Buy me a coffee 保留为次要入口，避免与购买 Pro 混淆。

## 客服入口更新（2026-11-27）

统一入口名称为“联系客服”，支持功能问题、付款与恢复购买。弹窗主操作“打开邮件应用”，通过 mailto 预填 sumei7550@outlook.com、主题“Tab Copier 客服支持”和可编辑问题模板；用户自行填写并发送，不自动发送。模板中付款邮箱和 PayPal 交易号仅在涉及付款/恢复时填写。不自动附带浏览数据、秘密凭证或付款详情。

保留复制邮箱和复制模板，处理默认邮件应用未配置的场景；不能承诺 mailto 在所有设备都能打开。“恢复购买”作为次要操作保留，上方说明“已购买？恢复 Pro 权益。”。点击先验证本设备凭证：有效则恢复；无凭证则引导联系客服；网络故障仅提示重试，不判断未购买。恢复本质仍是人工核实后的单次链接流程，不因改名降低鉴权。测试需核对中文主题/正文 URL 编码、用户确认发送、无邮件客户端备用入口、键盘焦点和恢复流程不变。

## 去重入口及规则（2026-11-27 确认）

支持序列号：首次安装自动生成 TC-随机安装标识并保持稳定，所有反馈邮件自动携带；恢复会话编号和秘密仅内部使用。普通反馈无需联网生成恢复请求。

- 弹窗保留“移除重复 URL · Pro”；设置页为“默认移除重复 URL · Pro”。两处映射同一个 removeDuplicates 偏好，修改后同步，不创建互相覆盖的第二套值。正式实现跨页面用 storage.onChanged 同步。
- 进入设置或查看去重选项不弹付费；免费用户尝试开启才显示 Pro 说明，可看套餐或取消。取消不保存开启状态；Pro 直接切换并更新预览。权益判断在处理输出的公共模块执行，不能仅凭按钮/本地布尔值放行；旧用户按最终迁移政策例外处理。
- 顺序：候选范围/筛选/勾选 → 按 removeTracking 处理 URL → 开启且有权益时去重 → 生成预览和复制文本。对相同的处理后完整 URL 保留第一条，不按标题/域名/网页内容合并，不新增参数排序、hash 删除或路径大小写折叠。
- 开启时显示“已排除 N 个重复链接 · 将复制 M 条”，无重复显示 0；选中数量保持真实勾选数，与输出数量分开。关闭后保留所有已选项。
- 列表保留原始候选以便用户决定选哪个标题；去重作用于已选输出，不提前永久隐藏重复候选。这是相比 1.2 加载时去重的有意调整。Pro 到期或无有效权益后，保留偏好但停止执行并同步预览。
- 搜索属于查找，去重属于输出整理；本版不新增复杂高级过滤菜单。
- 原型含一对仅追踪参数不同的示例链接，可切换 Pro、去重和追踪清理查看效果；模拟设置不跨刷新持久化。

## 支持序列号统一（最新交互）

普通反馈与恢复购买统一使用本安装的公开支持序列号 TC-随机安装标识。自动生成并随邮件/复制模板附带，用户不手动生成或填写；序列号不是付款、授权或购买归属证明，不是硬件指纹，重装可能变化。普通反馈只填问题描述，不要求交易信息，不请求恢复服务。点击“恢复购买”时才在内部建立私密恢复会话，UI 不再展示单独恢复编号；管理员用支持序列号定位有效会话，仍需独立核实付款归属。找不到会话时要求点击恢复购买，不凭序列号直接发授权。恢复接口仍使用独立私密凭证。

## 联系客服文案简化

不在用户页面展示安装标识或“支持序列号”及其解释。普通反馈和恢复邮件后台自动附带同一安装标识，邮件字段称“参考编号”；复制模板同样附带。页面仅保留联系、复制和恢复操作，成功反馈只说明已复制/请填写问题，不突出编号。测试需确保移除展示后没有遗留 DOM 引用，邮件/模板仍包含定位信息。该标识仍不能代替授权或付款归属验证。
