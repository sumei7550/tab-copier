# Tab Copier 1.3 版本计划

状态：规划，尚未实现。基于 1.2.0；不将计划能力宣传为已上线。

## 目标

回应用户对 Chrome 标签组的需求，并实现已确定的收费方案：免费基础复制每日 3 次，Pro 解锁无限次数、标签组、去重和 Markdown 列表样式。开发和发布只以技术可实现性及运行可靠性为条件，不将付费意愿、购买转化或先发布免费版作为前置条件。

## 功能与权益

| 功能 | 免费版 | 有效 Pro |
| --- | --- | --- |
| 当前标签页、当前窗口、全部窗口 | 每天共 3 次成功复制 | 不限次数 |
| 普通 Markdown 链接、标题 + URL、仅 URL、HTML 链接 | 支持，共用额度 | 支持 |
| Markdown 无序列表、有序列表、任务清单 | 不支持 | 支持 |
| 当前标签组范围、输出包含组名 | 不支持 | 支持 |
| 移除重复 URL | 不支持 | 支持 |
| 搜索筛选、逐项选择、全选、预览、刷新 | 支持，不扣次数 | 支持 |
| 排除固定标签、移除跟踪参数 | 支持 | 支持 |
| 固定工具栏引导 | 支持 | 支持 |

免费 Markdown 每行输出一个链接，不带列表标记。列表样式不是改变标签先后顺序；本版不增加拖动或按标题排序。

## 复制范围与界面

- 用范围下拉框替换 All windows：当前标签页、当前标签组、当前窗口、全部窗口。默认当前窗口。
- 当前标签组取打开 popup 前活动标签所属的 Chrome 标签组；未分组时禁用并提示原因。
- 范围切换后刷新候选标签、选择状态和预览；不保留已离开范围的选中项。
- 保留格式选择及独立的 Markdown style 行。付费选项显示 Pro 标记；点击可查看权益，不默默启用或扣额度。
- 标签组范围显示组名；包含组名作为可选输出，组名需按输出格式正确转义。
- 顶部显示“今日剩余 3 次”和升级入口；额度耗尽后仍允许查看、筛选和预览。
- Pro 到期后保留用户偏好，但实际输出回退到当前窗口、关闭去重、普通 Markdown，并明确提示；预览必须与实际复制一致。
- 首次安装提供固定工具栏步骤，读取固定状态后隐藏提示；不承诺自动固定。

## 套餐

所有付费套餐权益一致，仅有效期不同：

| 套餐 | 价格（USD） | 有效期与规则 |
| --- | --- | --- |
| 体验 | $0.99 | 首次激活起连续 72 小时；按可验证的付款方标识限制一次，跨账户无法保证 |
| 30 天 | $4.99 | 首次激活起连续 30 天；非自动续费 |
| 买断 | $12 | 本计划列明的 Pro 权益，无到期时间 |

本版不实现体验费抵扣，不承诺尚未上线的能力。有效期按支付服务可信时间计算，不按本机日期计算。重复购买、升级时长计算、退款与撤销规则在接入前明确；不能静默缩短已有权益。

支付采用 PayPal，用户现有账户为中国大陆 Personal。先使用沙盒验证完整支付授权链路，再核实正式环境订单验证/通知、退款及收款结算能力，正式账户验证不阻塞沙盒开发。沙盒卖家账户可用不代表现有 Personal 账户拥有正式商户 API 权限。不能以付款成功跳转或用户截图作为自动发码依据。暂不采用 ExtensionPay/Stripe。

支付流程包括升级页、结账跳转、支付状态刷新、恢复购买、失败重试、到期处理。短暂断网使用有期限的已验证权益缓存；未知或请求失败不能直接当作未购买。明确商户、支持方式和退款说明。

## 已确定的部署与授权方案

- Next.js App Router 构建精简官网，Route Handlers（Node.js runtime）提供服务端接口，统一部署在 Vercel：套餐、支付、领取激活码、激活说明、隐私与支持页面。网站工程建议位于 website/，与扩展独立构建和打包。
- Supabase PostgreSQL 保存订单和授权。不启用用户登录，不建用户表，不发送邮件；第一版不同时引入 Upstash 或 MongoDB Atlas。
- 插件内输入激活码，由 Vercel 接口验证并返回可缓存的授权；到期时间以服务端为准。数据库和支付密钥仅保存在服务端，扩展和网页不能直接读写授权表。
- 页面凭高强度随机领取凭证领取激活码；订单号不能充当领取权限。支持刷新后重复领取同一授权，领取所需秘密加密保存，激活码校验值单独保存；禁止写入日志或分析系统。
- 不做账号恢复。用户应自行保存激活码及领取凭证；丢失后凭交易信息人工核查恢复，不以截图单独认定付款。

最小数据结构：

| 表 | 内容与约束 |
| --- | --- |
| orders | 套餐、服务端固定金额/币种、支付状态、PayPal 订单/收款交易号、付款时间、领取凭证校验值；外部收款交易号唯一 |
| licenses | 关联订单、激活码校验值、首次激活时间、到期时间、撤销状态；每个订单最多一个授权 |

服务端核实收款方、金额、币种与最终收款状态，不能仅验证订单已创建或买家已批准。处理重复通知、并发领取与首次激活时使用事务/唯一约束，避免重复发码和延长有效期。退款/撤销同步撤销授权。记录不随套餐到期直接删除。

Supabase 免费版用于开发验证；低活跃可能自动暂停。正式收费前确认不会因低活跃中断的生产配置和备份恢复方案，不依赖人工恢复维持新用户激活。

## 免费额度

- 所有格式和免费范围共用每天 3 次；以剪贴板写入成功为扣减依据。
- 空选择、无可复制标签、预览、筛选、刷新、格式切换和失败均不扣减。
- 防止连续点击造成并发超额或重复扣减；正常重复成功复制算新的一次。
- 按设备本地日历日重置，在界面说明“本设备每天”；跨时区/修改时钟不得反复发放同日额度。
- 免费次数是本地软限制，卸载/清除数据可能重置，不宣称防绕过；严格跨设备配额需账号与后端，不在本版范围。
- 本版无文件下载，故界面用“复制次数”，避免“导出”让用户误以为已支持保存文件。

## 老用户迁移：上线前必须确定

用户已决定去重和列表样式属于 Pro，但尚未明确老用户是否保留原免费权益。

建议：检测从 1.2 或更早版本升级的本地安装，保留原有基础复制不限次数、去重和列表样式；新增标签组仍需 Pro。新安装使用新规则。该保留权益仅限本地安装，不承诺重装或跨设备恢复；若需要可恢复权益，需另行设计账号认领。

如果决定所有用户统一限制，则应在首次更新时明确说明权益变化，不静默改变输出。此决定必须在实现迁移前确认。

## 埋点与隐私

沿用 ext_ 前缀，网站未来用 web_。记录范围变更、标签组复制成功、配额耗尽提示、付费功能点击、升级页展示、套餐选择、支付跳转、已验证权益激活、恢复购买及套餐到期。

记录 plan、scope、format、markdown_style、result、reason 等枚举及必要数量；不记录组名、标题、URL、复制内容、邮箱、支付会话地址或支付凭据。支付页返回不等于购买成功，权益事件必须由可信支付状态确认并去重。

更新隐私政策、商店披露与产品说明，区分标签内容本地处理、Mixpanel 分析、PayPal 支付，以及 Vercel/Supabase 保存的订单与授权数据。按实际接入增加最小权限与 MV3 后台逻辑，不远程执行代码。

## 本版不做

TXT 新格式、文件下载、自定义模板、保存预设、导入恢复、云同步、AI、右键菜单、按域名分组。

## 实施顺序与发布条件

### 第一阶段：先验证沙盒闭环

1. 创建 PayPal 沙盒卖家、买家与测试应用，配置沙盒 API 凭据及 Webhook；不发生真实扣款。
2. 在 Vercel 测试环境服务端创建并捕获订单，核实最终收款状态，验证 Webhook 签名。
3. 将已确认的订单写入 Supabase 测试环境，以事务和唯一约束保证每笔订单只生成一个授权。
4. 页面凭领取凭证显示激活码，插件以最小激活入口验证授权；72 小时/30 天从服务端首次激活时起算，重复激活不重置。
5. 验证三个套餐，以及重复通知、重复捕获/领取、支付失败或取消、通知延迟、退款撤销、并发激活和套餐到期。Webhook 与主动核款到达顺序不同也不能重复发码或恢复已撤销授权。

第一阶段产物是“沙盒付款 → 服务端核实 → 数据库订单 → 页面领码 → 插件激活”的可复核闭环，不要求先完成所有插件界面。

### 第二阶段：完成插件与运营规则

1. 确认老用户迁移、设备使用边界、到期/重复购买和人工恢复规则，冻结权益表。
2. 实现范围下拉、标签组读取和预览；统一免费额度、Pro 判断、到期回退及离线宽限，完成所有现有语言文案。
3. 完善套餐页、领码、激活/恢复入口和首次安装引导，补充埋点、隐私政策及商店披露。
4. 验证免费/体验/30天/买断/老用户，以及断网、跨日、无组、窗口切换、快速连点和数据库不可用。

### 第三阶段：正式环境与发布

1. 核实现有账户的正式 API、Webhook、退款及收款结算能力；如不具备权限，先解决账户资格，不能以沙盒通过替代正式验证。
2. 隔离沙盒和正式数据库、支付凭据、Webhook 配置及授权信任环境；正式插件不接受沙盒激活码。密钥仅在服务端保存。
3. 正式环境完成受控的真实付款、领码、激活与退款撤销验证。正式扣款属于单独的金融操作，执行前由用户明确授权或亲自完成。
4. 确认数据库生产配置与恢复措施、预览与复制一致、已付费不扣额度、无敏感内容上传，再构建 dist/zip 并发布 1.3.0。

正式支付能力及上述技术门槛通过前不开放真实收费。不以用户是否愿意购买作为上线门槛。本次仅更新计划，不触发代码实现、提交或发布。
