# Tab Copier 官网 MVP

> 规划稿，供用户确认后交给 Codex 执行。当前工作区未发现现有网站/插件仓库，商店页面不可直接读取；因此先定范围和事实门槛，不生成实施代码。

## 网站目标

1. 让访客立即理解扩展实际解决的任务和限制。
2. 用可核实的产品截图、权限/隐私信息建立信任。
3. 将有安装意图的访客送到官方 Chrome Web Store 页面。
4. 为有限数量、各有独立价值的搜索意图提供可索引页面。

核心衡量：商店 CTA 点击率、自然搜索点击/展示及落地页表现。CTA 点击不是安装量；若无法合规获得商店安装数据，不把点击包装成安装转化。

## 网站范围与信息架构

```text
/
├── /privacy
├── /copy-chrome-tabs             （P1 候选；事实与 SERP 验证后决定）
├── /chrome-tabs-to-markdown      （P1 候选；事实与 SERP 验证后决定）
└── /guides/copy-open-chrome-tabs （P2；有原创步骤/截图后再做）
```

MVP 发布建议先做首页与隐私页；高意图专题页只有在内容真实、与首页意图不同并通过 SEO 研究后才纳入。没有内容策略、维护责任和原创文章时不搭建博客系统。

## 首页模块

1. **导航：** 品牌名称/图标、Features/How it works 锚点、Privacy、清楚的安装 CTA。
2. **Hero：** 一句准确说明实际任务的标题、简短解释、主 CTA；紧邻放当前扩展 UI 截图。功能事实未确认前不定稿文案。
3. **真实操作演示：** 选择标签 → 预览 → 复制的流程（若实际版本确实如此）；说明窗口范围和 Chrome 内部页限制。
4. **格式展示：** 仅展示经当前版本确认的输出格式，并使用真实、脱敏样例。
5. **核心功能：** 只列 PRODUCT_FACTS 中已核实能力；每项配真实界面或明确说明。
6. **场景：** 研究、学习、写作等作为使用情境而不是新功能承诺；只有能写出具体、真实工作流时保留。
7. **隐私与权限：** 简洁说明数据流、权限原因并链接完整隐私政策；以源码/政策为依据。
8. **FAQ：** 能复制哪些标签、格式是什么、快捷键怎么配置、数据是否上传、为什么需要权限、哪些页面受 Chrome 限制、是否收费等；答案核实后再公开。
9. **页尾 CTA 与页脚：** 商店链接、隐私页、联系渠道（需用户提供）、版权/法律信息（需核实）。

## 内容与素材要求

- 主语言及是否提供中文版本由目标市场决定；避免自动逐词翻译造成不准确的功能说明。
- Logo、商店图标、扩展实际界面截图、使用步骤需来自用户/仓库，并确认使用权。不得用竞品截图或模拟界面冒充真实产品。
- Hero 与每个专题页采用真实功能描述；在 PRODUCT_FACTS 有待核验标记时，不写绝对隐私/安全声明、用户数、评分或搜索效果。
- 隐私页逐项对应实际权限、处理、存储、网络传输、保留和联系信息；不从模板复制与实现不符的说法。法律要求需按经营地区和实际数据处理另行确认。
- 安装 CTA 统一指向给定商店链接；可用带 `rel="noopener"` 的新标签行为（如采用新标签），链接失效时页面应便于更新。

## 技术建议

- 若无既有项目约束：沿用用户偏好的 **Next.js App Router + TypeScript + Tailwind CSS + Vercel**。
- 当前未检查到项目文件，不能确认仓库框架或目录；本地 Codex 执行前先定位实际仓库，若现有网站技术栈可维护且满足 SEO，则先评估复用，避免无故重建。
- 首页与静态内容优先服务器渲染/静态生成；客户端 JS 保持克制。避免仅客户端注入关键 SEO 正文。
- 使用 Next.js Metadata API 管理 canonical、页面 metadata、Open Graph；生成 `robots.txt` 和 sitemap。参考 [Metadata API](https://nextjs.org/docs/app/getting-started/metadata-and-og-images) 与 [sitemap 文件约定](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/sitemap)。
- Vercel 作为部署候选；域名、DNS、GSC 验证和正式发布都在用户确认域名/账号后执行。本轮不部署。
- 分析与 cookie：MVP 不默认接入第三方追踪。若以后需要，先确定同意机制、隐私披露与最小化埋点。

## 验收标准

- 所有公开功能、权限、费用和隐私表述都能回指 PRODUCT_FACTS 的已核实证据；未知项不以肯定语气发布。
- Chrome Web Store CTA 指向正确官方条目，在桌面和移动布局均可见、可操作。
- 页面移动端可读、键盘可操作、文本有语义层级、图片有合适替代文本；颜色对比达可读水平。
- 每个索引页有唯一 title、description、H1、canonical、足够原创正文、站内链接和明确用户意图；薄内容页不发布/不索引。
- 首页、隐私页及已批准专题页返回正确状态码；不存在错误重定向、空链接、未处理 404、意外 `noindex`。
- 生产域名下 `robots.txt` 与 sitemap 可访问，sitemap 只含 canonical 且允许索引的正式 URL；Search Console 可验证并提交。
- 结构化数据若有，仅用于页面可见且真实的实体信息；验证无错误，并不把富结果作为验收保证。
- Vercel Preview 上完成内容、链接、SEO metadata、响应式、可访问性、性能及关键浏览器人工复核；上线需用户单独确认。
- 安装按钮点击可计数时清楚标记为站内 CTA 事件，不称为扩展安装量。
